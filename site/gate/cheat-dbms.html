// SQLorder & gotchas
SELECT … FROM … WHERE … GROUP BY … HAVING … ORDER BYlogical order: FROM→WHERE→GROUP→HAVING→SELECT→ORDER.
WHERE filters rows; HAVING filters groupsaggregates only in HAVING/SELECT.
aggregates: COUNT,SUM,AVG,MIN,MAXignore NULLs (except COUNT(*)).
NULL: any comparison → UNKNOWNuse IS NULL; 3-valued logic.
joins: INNER, LEFT/RIGHT/FULL OUTERouter keeps unmatched rows (NULLs).
DISTINCT, IN, EXISTS, correlated subqueryEXISTS often faster than IN.
// normalizationmost tested
FD X→Y: X determines Yfunctional dependency.
1NF: atomic values, no repeating groups
2NF: 1NF + no partial dependencynon-prime fully depends on whole key.
3NF: 2NF + no transitive dependencynon-prime → non-prime banned.
BCNF: every determinant is a super keystricter than 3NF.
find candidate keys via attribute closure X⁺key step in every normalization Q.
prime attribute = part of some candidate keydefines partial/transitive tests.
// indexing & file organizationaccess
primary (clustered) index: on sort key, 1 per tabledata ordered by it.
secondary (non-clustered): many, denseextra lookup.
B/B+ tree: O(log n) search; B+ leaves linkedrange queries fast on B+.

// data transformation & warehousingOLAP
transforms: normalization (scale), discretization, sampling, compressionpreprocessing.
min-max scale: (x−min)/(max−min) · z-score: (x−μ)/σfeature normalization.
star schema: 1 fact + denormalized dimensionsfast, some redundancy.
snowflake: dimensions normalizedless redundancy, more joins.
fact table = measures; dimension = contextconcept hierarchies (day→month→year).
OLAP ops: roll-up, drill-down, slice, dice, pivotmeasures: additive / semi / non-additive.

exam traps

  • WHERE vs HAVING — WHERE before grouping (rows), HAVING after (groups/aggregates).
  • NULL logic — comparisons with NULL give UNKNOWN, not TRUE/FALSE; use IS NULL.
  • Find candidate keys first via attribute closure — every normalization question hinges on it.
  • 2NF removes partial, 3NF removes transitive, BCNF: determinant must be super key — know which dependency each removes.
  • Primary/clustered index: only one per table; secondary can be many.
  • π (projection) removes duplicates in relational algebra (set semantics) — SQL SELECT keeps them unless DISTINCT.
  • Normalization is the highest-frequency topic — master attribute closure, candidate keys, and the 1NF→BCNF ladder.
  • SQL: know the logical evaluation order and NULL three-valued logic cold.
  • Indexing: clustered vs non-clustered, B+ for ranges, hash for point queries.
  • Warehousing: star vs snowflake, fact/dimension, OLAP operations, measure types.
