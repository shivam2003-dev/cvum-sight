// what this page is

Why A* is optimal, how alpha-beta pruning works, what d-separation tells you, and how variable elimination computes a Bayesian-network query — with worked traces. Memorize the search-algorithm grid (complete/optimal/complexity) and master A* admissibility and Bayes-net inference; those carry the marks. Pair with the cheatsheet; reasoning leans on Prob/Stats.

AI here is three skills: search a space of states to reach a goal, reason with logic, and reason under uncertainty with probabilities. Each has one or two ideas that everything else hangs off — get those and the question types become mechanical.

01 Uninformed search

key ideaWith no hints about distance to the goal, you explore by structure. BFS expands shallowest first (queue) — finds the fewest-edges path. DFS goes deepest first (stack) — cheap memory, but can wander. UCS expands the lowest cumulative-cost node — optimal for weighted graphs.

Fig — the search grid GATE tests (b=branching, d=depth, m=max depth). DFS not complete in infinite spaces.

02 Informed search & why A* is optimal

key ideaA* ranks nodes by f(n) = g(n) + h(n) — cost so far plus an estimate of cost to go. It blends UCS (the g) with a goal-directed pull (the h), expanding the node that looks cheapest end-to-end.

When is A* optimal?

  1. Admissible heuristic: h never overestimates the true remaining cost (h ≤ h*). → optimal for tree search.
  2. Consistent (monotonic): h(n) ≤ cost(n,n′) + h(n′). → optimal for graph search too. Consistent ⇒ admissible.
why admissibility worksIf h never overestimates, A* can't be fooled into finalizing a goal via an expensive path while a cheaper one is still "optimistically" pending — the cheaper path's f stays low enough to be expanded first. Overestimate, and A* might lock in a worse path. h=0 makes A* = UCS (safe but slow); the closer h is to h* without exceeding it, the faster.

03 Adversarial search — minimax & alpha-beta

key ideaMinimax: you maximize, the opponent minimizes, alternating down the game tree; values back up from the leaves. Alpha-beta pruning skips branches that can't change the decision — same answer, far less work.

How alpha-beta prunes

  1. α = best value MAX can guarantee so far; β = best MIN can guarantee.
  2. Explore depth-first, updating α (at MAX nodes) and β (at MIN nodes).
  3. Prune when α ≥ β: the opponent would never let play reach this branch.
the catchAlpha-beta gives the same value as plain minimax — pruning never changes the answer, only the work. With perfect move ordering it explores O(bm/2) instead of O(bm), effectively doubling the searchable depth.

04 Logic — propositional & predicate

  • Propositional: statements that are true/false, combined with ¬ ∧ ∨ → ↔. Key equivalences: A→B ≡ ¬A∨B; contrapositive A→B ≡ ¬B→¬A; De Morgan ¬(A∧B) ≡ ¬A∨¬B.
  • Predicate (first-order): adds quantifiers ∀ (all) and ∃ (exists) over objects. ¬∀x P(x) ≡ ∃x ¬P(x).
termsValid = true in every interpretation (tautology). Satisfiable = true in at least one. Entailment KB ⊨ α: α holds in every model where KB holds.

05 Bayesian networks

key ideaA Bayes net is a DAG where each node is a variable and edges encode direct dependence. The whole joint distribution factors as P(X₁…Xₙ) = Π P(Xᵢ | parents(Xᵢ)) — a compact stand-in for an exponential table.
worked — joint from the netNet A→C←B. Joint = P(A)·P(B)·P(C|A,B). To get P(C), sum the product over A and B (variable elimination).

06 d-separation — reading independence off the graph

key idead-separation tells you whether two variables are conditionally independent given evidence, just from the graph shape. Three connection types behave differently:
  • Chain A→B→C and fork A←B→C: information flows through B, but blocked when B is observed.
  • Collider A→B←C: blocked by default, but opens when B (or a descendant) is observed — "explaining away."
the catch — the collider flipThe collider is the trap: observing the common effect makes its two causes dependent (the opposite of chains/forks). E.g. alarm caused by burglary or earthquake — learning it was an earthquake lowers the chance of burglary given the alarm rang.

07 Inference — variable elimination & sampling

Exact: variable elimination

  1. Write the joint as the product of CPTs.
  2. Push summations inward; sum out (eliminate) non-query, non-evidence variables one at a time, forming intermediate factors.
  3. Multiply remaining factors, normalize → the posterior.

Approximate: sampling when exact is too costly — draw samples consistent with the network (e.g. likelihood weighting, Gibbs) and estimate probabilities by frequency.

08 The master decision tree

Read the question → branch

  1. "Complete/optimal/complexity of a search" → the grid (§01–02).
  2. "Will A* find the optimal path" → check admissible/consistent (§02).
  3. "Value at the root / which branch pruned" → minimax + α≥β (§03).
  4. "Are X,Y independent given Z" → d-separation, watch colliders (§06).
  5. "Compute P(query|evidence)" → factor the joint, eliminate variables (§05,§07).
  6. "Valid/satisfiable/entails" → logic equivalences & models (§04).

09 The high-frequency exam traps

memorize these

  • A* optimal ⇔ admissible (tree) / consistent (graph); consistent ⇒ admissible.
  • Admissible = never overestimates h ≤ h*; h=0 makes A* = UCS.
  • Alpha-beta = same value as minimax, only faster; prune when α≥β.
  • DFS not complete in infinite spaces; BFS optimal only for unit costs (use UCS otherwise).
  • Collider opens when observed; chain/fork block when observed.
  • Joint = Π P(node|parents); inference = sum out the rest.
  • A→B ≡ ¬A∨B, contrapositive equivalent, converse is NOT.

10 FAQ

Admissible vs consistent — which do I need?

Admissible (h ≤ true cost) guarantees optimal A* for tree search. Consistent (the triangle inequality on h) is stronger and guarantees optimality for graph search with no re-expansions. Every consistent heuristic is admissible, not vice versa.

Does alpha-beta change the result?

No. It returns the exact minimax value; it only avoids exploring branches that can't affect the decision. Move ordering affects how much it prunes, not correctness.

Why do two causes become dependent at a collider?

Observing the common effect means the causes must "compete" to explain it — confirming one makes the other less needed. This "explaining away" is unique to colliders; chains and forks block when the middle node is observed.

  • Memorize the search grid; the marks are nearly free.
  • A* optimal ⇔ admissible/consistent heuristic — the most-tested AI fact.
  • Alpha-beta = minimax value, less work; prune at α≥β.
  • For Bayes nets: joint = Π P(node|parents), watch the collider in d-separation, and infer by variable elimination.
