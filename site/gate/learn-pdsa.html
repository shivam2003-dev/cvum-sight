// what this page is

Why each data structure has the complexity it has, when to reach for which algorithm, and how to trace the algorithm GATE puts in front of you. Most questions are "state the complexity" or "trace this on an input" — both become automatic once the mental models below click. Pair with the cheatsheet.

Two questions answer almost everything here: "how is the data laid out in memory?" (that fixes the data-structure costs) and "how does the work shrink each step?" (that fixes the algorithm's complexity). Memorizing tables is fragile; understanding these two ideas makes the tables re-derivable.

01 Big-O — counting growth, not seconds

key ideaBig-O describes how the running time grows as input n grows, ignoring constants and small terms. O(1) flat, O(log n) barely grows, O(n) linear, O(n log n) good sorts, O(n²) nested loops, O(2ⁿ) exponential blow-up.

How to read complexity off code

  1. Single loop over n → O(n). Nested loop → multiply → O(n²).
  2. Halving the problem each step → O(log n) (binary search, balanced-tree height).
  3. Halve and do O(n) work per level → O(n log n) (merge sort).
  4. Recurrence? Apply the Master theorem (§05).

02 Data structures — layout decides cost

think of it likeAn array is houses on one street — instant jump to any number (index), but inserting in the middle shifts everyone. A linked list is a treasure hunt — each node points to the next, so insert is cheap but reaching the k-th means walking from the start.
  • Array: access O(1), search O(n), insert/delete O(n) (shifting).
  • Linked list: access/search O(n), insert/delete at a known node O(1).
  • Stack (LIFO) / Queue (FIFO): push/pop/enqueue/dequeue O(1).
  • Hash table: average O(1) insert/search/delete; worst O(n) under heavy collisions.
  • Binary heap: insert & extract-min/max O(log n); peek O(1). Backbone of priority queues.
  • BST (balanced): search/insert/delete O(log n); degenerates to O(n) if unbalanced (inserting sorted data builds a linked list).
the catchHash and BST give their nice bounds only conditionally. Hash O(1) is average — adversarial keys collide to O(n). BST O(log n) needs balance — sorted insertions make it O(n). GATE loves the worst case.

03 Searching

  • Linear search — O(n), works on any list.
  • Binary search — O(log n), but only on sorted data. Each step throws away half the remaining range.

04 Sorting — know best/avg/worst + stability

Fig — the sort table GATE tests. Memorize the worst-case column and the stability column.

the trapsQuicksort worst case is O(n²) (already-sorted input with bad pivot), not O(n log n). Merge sort is always O(n log n) and stable but needs O(n) extra space. A stable sort keeps equal elements in their original order — matters when sorting records by a secondary key.

05 Divide-and-conquer & the Master theorem

key ideaD&C splits a problem into a subproblems of size n/b, with O(nd) work to combine: T(n)=a·T(n/b)+O(nd). Compare the split rate to the combine cost.

Master theorem — compare d to log_b a

  1. d < log_b a → leaves dominate → O(nlog_b a).
  2. d = log_b a → balanced → O(nd log n).
  3. d > log_b a → root dominates → O(nd).
workedMerge sort: a=2, b=2, d=1. log₂2 = 1 = d → case 2 → O(n log n). Binary search: a=1, b=2, d=0. log₂1=0=d → O(log n).

06 Graph algorithms — pick by the question

  • BFS — layer by layer (queue). Shortest path in unweighted graphs. O(V+E).
  • DFS — go deep (stack/recursion). Cycle detection, topological sort, connectivity. O(V+E).
  • Dijkstra — shortest path, non-negative weights, greedy with a min-heap. O((V+E)log V).
  • Bellman-Ford — shortest path that handles negative edges and detects negative cycles. O(VE).
  • Topological sort — linear order of a DAG so every edge points forward (task scheduling).

How to choose the graph algorithm

  1. Unweighted shortest path → BFS.
  2. Weighted, all weights ≥ 0 → Dijkstra.
  3. Negative weights / detect negative cycle → Bellman-Ford.
  4. Ordering tasks with dependencies → topological sort (DFS-based).
the catchDijkstra breaks with negative edges — its greedy "finalize the nearest" assumption fails. Switch to Bellman-Ford. This choice is a classic exam discriminator.

07 The master decision tree

Read the question → branch

  1. "What's the complexity of this code/structure-op" → §01–02 tables.
  2. "Trace this algorithm on input X" → walk it step by step, write each state (§03–04, §06).
  3. "Solve this recurrence" → Master theorem (§05).
  4. "Which algorithm should be used" → match weights/ordering to §06.
  5. "Worst vs average" → recall the conditional bounds (hash, BST, quicksort).

08 The high-frequency exam traps

memorize these

  • Quicksort worst = O(n²); merge sort always O(n log n) but O(n) extra space.
  • Binary search needs sorted data.
  • Hash O(1) is average; worst O(n). BST O(log n) needs balance; else O(n).
  • Dijkstra fails on negative edges → Bellman-Ford.
  • BFS = unweighted shortest path, DFS ≠ shortest path.
  • Stable sorts: bubble, insertion, merge. Unstable: selection, quick, heap.
  • Master theorem: compare d with log_b a — don't guess.

09 FAQ

Why is quicksort used if its worst case is O(n²)?

In practice its average is O(n log n) with small constants and good cache behaviour, and randomized pivots make the worst case vanishingly unlikely. GATE still tests the worst case because it's the conceptual gotcha.

BFS or DFS for shortest path?

BFS for unweighted graphs (it explores in distance order, so the first time you reach a node is via a shortest path). DFS does not give shortest paths. For weighted graphs use Dijkstra/Bellman-Ford.

What makes a sort "stable" and why care?

Equal-key elements keep their input order. It matters when sorting by multiple keys in passes (e.g. sort by name, then stably by department) — instability would scramble the earlier ordering.

  • Memory layout fixes data-structure costs; how the work shrinks fixes algorithm complexity.
  • Know the sort table (worst case + stability) and the conditional bounds (hash/BST/quick) cold.
  • Master theorem handles every recurrence — compare d to log_b a.
  • Choose graph algorithms by weights and ordering; Dijkstra ≠ negative edges.
