LangChain — the standard library for LLM apps.

agent-framework ai-native langchain llm python

TL;DR — LangChain is the glue between your code and any LLM. It standardizes prompts, models, tools, memory, and retrieval behind one interface so you can swap providers and compose multi-step apps without rewrites. Start here; reach for LangGraph when you need real control flow.

What it is

LangChain is an open-source framework for building applications on top of large language models. It gives you a common abstraction over model providers (OpenAI, Anthropic, local models via Ollama, etc.) plus batteries-included pieces — prompt templates, output parsers, tool calling, retrieval, and memory — wired together with a composition syntax called LCEL (LangChain Expression Language).

In the AI Native landscape it sits in AI Agent › Agent Framework: the application layer that turns a raw model endpoint into an app that retrieves context, calls tools, and runs multi-step logic.

Why it exists

Calling one model once is a single HTTP request — you don't need a framework for that. The pain shows up the moment you do real work: you want to swap GPT-4 for Claude without rewriting, chain a retrieval step into a prompt, parse the model's output into a typed object, give it tools, and remember the conversation. Hand-rolling all of that means reinventing the same plumbing in every project.

LangChain exists to make those pieces interchangeable and composable. A retriever is a retriever; a chat model is a chat model. You write against the interface, not the vendor.

Core concepts

  • Chat models — uniform wrapper over any provider. model.invoke(messages) works the same whether it's OpenAI or a local Llama.
  • Prompt templates — parameterized prompts you fill at runtime instead of f-string spaghetti.
  • LCEL & Runnables — the | pipe operator composes steps into a chain. Every piece is a Runnable with invoke/batch/stream.
  • Output parsers — turn raw text into strings, JSON, or Pydantic objects.
  • Tools & tool calling — expose Python functions the model can decide to call.
  • Retrievers & vector stores — the RAG layer: embed documents, fetch the relevant ones, stuff them into the prompt.
  • Memory — persist conversation state across turns.

Install & hello world

pip install langchain langchain-openai
export OPENAI_API_KEY=sk-...
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

model  = ChatOpenAI(model="gpt-4o-mini")
prompt = ChatPromptTemplate.from_template("Explain {topic} in one sentence.")
chain  = prompt | model | StrOutputParser()

print(chain.invoke({"topic": "vector databases"}))

That prompt | model | StrOutputParser() pipeline is LCEL — three Runnables composed into one. Swap ChatOpenAI for ChatAnthropic and nothing else changes.

A real use — minimal RAG

The most common LangChain app: answer questions over your own documents.

from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_core.vectorstores import InMemoryVectorStore
from langchain_core.prompts import ChatPromptTemplate

docs = ["LangChain standardizes LLM apps.",
        "LangGraph adds stateful, cyclic control flow."]
store     = InMemoryVectorStore.from_texts(docs, OpenAIEmbeddings())
retriever = store.as_retriever(search_kwargs={"k": 2})

prompt = ChatPromptTemplate.from_template(
    "Answer using only this context:\n{context}\n\nQ: {q}")
model  = ChatOpenAI(model="gpt-4o-mini")

def rag(q):
    ctx = "\n".join(d.page_content for d in retriever.invoke(q))
    return model.invoke(prompt.format(context=ctx, q=q)).content

print(rag("What does LangGraph add?"))

Embed → retrieve → stuff into prompt → answer. Every box here is swappable: the vector store, the embedder, the model.

When to use, when to skip

Use it when you're prototyping fast, want provider portability, or need the huge ecosystem of off-the-shelf integrations (loaders, vector stores, tools). It's the fastest path from idea to working LLM app.

Skip it for a single dumb API call — the SDK is enough. For complex, long-running, branching agent logic, graduate to LangGraph (explicit state machine). Teams who want strict typing sometimes prefer Pydantic AI or thin custom wrappers instead.

gotcha The framework moves fast and has churned APIs across versions. Pin your versions, and prefer langchain-core + the specific provider package (langchain-openai) over the monolithic langchain meta-package to keep your dependency surface small.
