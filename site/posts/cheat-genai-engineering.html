CHEATSHEET · GENAI · APPLIED LLM SYSTEMS

GenAI Engineering — The Applied Cheatsheet.

genai rag agents llm-apps
Building with LLMs is mostly context engineering and evaluation, not model training. The model is a fixed black box; your job is to get the right tokens into the prompt, constrain the output, measure quality honestly, and keep cost/latency sane. This is the applied stack.

1. The capability ladder (cheapest first)

  1. Prompt engineering — instructions, examples, format. Always start here.
  2. RAG — inject retrieved knowledge. For facts/freshness/private data.
  3. Tools / function calling — let the model act (search, code, APIs).
  4. Agents — multi-step loops with memory + tools. For open-ended tasks.
  5. Fine-tuning — last resort, for style/format/latency, not for facts.
don't fine-tune for knowledge Fine-tuning teaches behaviour/format, not facts — and it bakes them in stale. For knowledge that changes or must be cited, use RAG. Reach for fine-tuning to fix tone, structure, or to shrink a big prompt into the weights for latency.

2. Prompting that holds up

  • Be explicit: role, task, constraints, output format. Show 1–3 examples (few-shot) for tricky formats.
  • Chain-of-thought / reasoning for multi-step problems; with reasoning models, ask for the answer and let them think internally.
  • Structured output — JSON schema / constrained decoding (grammars) so downstream parsing never breaks.
  • Put stable content (system prompt, instructions) first → it's prefix-cacheable. Keep the variable bit at the end.

3. RAG pipeline

ingest → chunk → embed → index            (offline)
query → embed → retrieve → rerank → pack → generate → cite   (online)
  • Chunking — semantic / structure-aware beats fixed size; keep chunks self-contained, add overlap + metadata.
  • Hybrid retrieval — dense (embeddings) + sparse (BM25) + a reranker (cross-encoder). Hybrid + rerank beats pure vector almost always.
  • Vector stores — pgvector, Qdrant, Weaviate, Milvus, FAISS (local). Postgres+pgvector is the boring, correct default.
  • Advanced: query rewriting, HyDE, parent-document / small-to-big, GraphRAG for connected facts.
retrieval quality is the ceiling A great model can't answer from bad context. Most "the LLM is dumb" bugs are retrieval bugs — wrong chunks, no reranker, chunk too big/small. Evaluate retrieval (recall@k, hit rate) separately from generation.

4. Agents & tools

  • Loop: model reasons → picks a tool → gets the result → repeats until done (ReAct-style).
  • Function calling — define tools as schemas; the model emits a structured call you execute and feed back.
  • MCP (Model Context Protocol) — open standard for connecting models to tools/data sources; the emerging integration layer.
  • Frameworks: LangGraph (graphs/state), the OpenAI Agents SDK, CrewAI, plain function-calling loops. Start with the simplest that works.
  • Keep agents bounded: step limits, tool allow-lists, timeouts, human-in-the-loop for risky actions.

5. Context window management

  • Long context ≠ free: cost + latency grow, and models suffer "lost in the middle" — info mid-prompt gets ignored. Put critical content at the start or end.
  • Summarize / compress history; retrieve only what's needed instead of dumping everything.
  • Track token budget per request; trim conversation memory with windowing or summarization.

6. Evaluation (the part everyone skips)

  • Build a golden eval set from real queries early. You can't improve what you don't measure.
  • LLM-as-judge for open-ended quality (calibrate against human labels); exact/structured checks where possible.
  • RAG metrics: faithfulness (grounded in context?), answer relevance, context precision/recall (RAGAS-style).
  • Run evals in CI on every prompt/model change — prompts are code and regress silently.
  • Tools: RAGAS, promptfoo, LangSmith, Braintrust, OpenAI Evals.

7. Safety & reliability

  • Prompt injection is the top risk — untrusted content (retrieved docs, tool output, user input) can hijack instructions. Never trust retrieved text as commands; separate data from instructions; constrain tool permissions.
  • Hallucination control — ground with RAG, require citations, ask "I don't know" when unsupported, verify with a second pass.
  • Guardrails — input/output validation, PII redaction, content filters, schema validation.
  • Cap blast radius of tool use (no raw shell/db write without checks).

8. LLMOps — cost, latency, observability

  • Cache aggressively: exact-match, semantic cache, and prompt-prefix caching for repeated system prompts.
  • Route by difficulty: small/cheap model for easy turns, big model for hard ones (model cascades / routers).
  • Stream tokens for perceived latency; measure TTFT + cost/request + tokens/request.
  • Trace every call (prompt, retrieved context, tool calls, tokens, latency, cost). You cannot debug a black box without traces.
  • Set budgets/rate limits; watch for runaway agent loops burning tokens.

9. Quick reference

Order: prompt → RAG → tools → agents → fine-tune (last)
RAG = hybrid retrieval + rerank; eval retrieval separately
Output = constrained JSON/grammar so parsing never breaks
Agents = bounded loops + function calling + MCP tools
Eval = golden set + LLM-judge + RAGAS, run in CI
Safety = treat retrieved/tool text as untrusted (prompt injection)
Ops = cache + route + stream + trace; watch cost/TTFT

10. Interview Q&A

  • RAG vs fine-tuning — when each?RAG for knowledge: facts, freshness, private/citable data. Fine-tuning for behaviour: tone, format, structure, or compressing a long prompt for latency. Knowledge changes, so don't bake it into weights.
  • Why add a reranker to RAG?Embedding retrieval is fast but coarse; a cross-encoder reranker scores query-document pairs jointly and reorders the top-k, sharply improving the context the model sees. Hybrid + rerank is the standard.
  • What is prompt injection and how do you mitigate it?Untrusted text (retrieved docs, tool output, user input) containing instructions that hijack the model. Mitigate by separating data from instructions, never executing retrieved text as commands, constraining tool permissions, and validating outputs.
  • How do you evaluate a RAG system?Separately measure retrieval (recall@k, context precision/recall) and generation (faithfulness, answer relevance) on a golden set, e.g. RAGAS. Run it in CI so prompt/model changes don't regress silently.
  • What is 'lost in the middle'?Models attend best to the start and end of a long context and can miss info in the middle. Put critical content at the edges, retrieve less but better, and don't assume bigger context fixes quality.
  • How do agents decide what to do?A reason-act loop: the model reasons, emits a structured tool call, you execute it and feed back the result, repeat until done. Bound it with step limits, allow-lists, and timeouts.
  • What is MCP?Model Context Protocol — an open standard for connecting LLMs to external tools and data sources through a common interface, instead of bespoke per-tool glue.
  • How do you cut LLM cost and latency in production?Prompt/semantic/prefix caching, route easy requests to smaller models, stream tokens, trim context, quantized serving, and budget/limit agent loops. Trace everything to find the spend.
  • How do you reduce hallucination?Ground answers in retrieved context, require citations, allow 'I don't know', constrain output format, and verify with a second check. Most of it is a retrieval/grounding problem.
  • Why constrain output to a schema?Downstream code needs reliable structure; constrained decoding / JSON-schema / grammars guarantee parseable output instead of hoping the model formats correctly.
