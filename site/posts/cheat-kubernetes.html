Kubernetes — The Interview Cheatsheet.

kubernetes orchestration devops interview-prep
Architecture Objects kubectl Pod spec Workloads Services Config & Secrets Storage Scheduling Probes Rollouts RBAC Autoscaling Debug Interview Q&A
The one-liner: Kubernetes is a declarative control loop. You declare desired state (YAML), controllers continuously reconcile actual → desired. You never "start a container"; you tell K8s what you want and it makes reality match.

1. Architecture

Control plane (the brain):

ComponentJob
kube-apiserverFront door. All reads/writes go through it. The only thing that talks to etcd.
etcdKey-value store = the single source of truth for cluster state.
kube-schedulerAssigns Pods to Nodes based on resources, affinity, taints.
controller-managerRuns control loops (Deployment, ReplicaSet, Node controllers) reconciling state.
cloud-controller-managerIntegrates cloud provider (LB, volumes, nodes).

Worker node (the muscle):

ComponentJob
kubeletNode agent. Talks to API server, ensures the Pod's containers are running & healthy.
kube-proxyPrograms iptables/IPVS for Service networking on the node.
container runtimeActually runs containers (containerd, CRI-O).

2. Core objects

ObjectWhat it does
PodSmallest deployable unit. One or more containers sharing network + storage. Usually not created directly.
ReplicaSetKeeps N identical Pods running. Managed by Deployment.
DeploymentDeclarative updates for Pods/ReplicaSets — rolling updates, rollback. The workhorse.
ServiceStable network endpoint + load balancing across a set of Pods.
IngressHTTP(S) routing into the cluster (host/path → Service).
ConfigMap / SecretInject config / sensitive data into Pods.
NamespaceVirtual cluster for isolation/quotas.
StatefulSetStable identity + storage for stateful apps (DBs).
DaemonSetOne Pod per node (log/metrics agents).
Job / CronJobRun-to-completion / scheduled tasks.

4. Pod spec anatomy

apiVersion: v1
kind: Pod
metadata:
  name: web
  labels: { app: web }
spec:
  containers:
    - name: web
      image: nginx:1.27
      ports: [{ containerPort: 80 }]
      env:
        - name: LOG_LEVEL
          value: info
      resources:
        requests: { cpu: "100m", memory: "128Mi" }   # scheduler reserves
        limits:   { cpu: "500m", memory: "256Mi" }   # hard cap (OOMKill if exceeded)
      readinessProbe:
        httpGet: { path: /healthz, port: 80 }
        initialDelaySeconds: 5
      livenessProbe:
        httpGet: { path: /healthz, port: 80 }
requests vs limits requests = what the scheduler guarantees/reserves (drives placement). limits = hard ceiling. Exceed memory limit → OOMKilled. Exceed CPU limit → throttled (not killed). No requests set → poor scheduling + first to be evicted.

6. Services & networking

TypeExposure
ClusterIPDefault. Internal-only virtual IP. Pod-to-pod.
NodePortOpens a port on every node (30000–32767). Basic external access.
LoadBalancerProvisions a cloud LB → Service. Standard external entry.
ExternalNameCNAME to an external DNS name.
IngressNot a Service type — L7 router (host/path) in front of Services.
 
apiVersion: v1
kind: Service
metadata: { name: web }
spec:
  selector: { app: web }       # matches Pod labels
  ports: [{ port: 80, targetPort: 80 }]
  type: ClusterIP

Service discovery: Services get a DNS name <svc>.<namespace>.svc.cluster.local. A Service finds its Pods via the label selector → maintains an Endpoints list. Pod networking itself is a CNI plugin (Calico, Cilium, Flannel) — flat network, every Pod gets a routable IP.

selector mismatch A Service with no matching Pod labels has empty Endpoints → "connection refused" with zero obvious errors. Check kubectl get endpoints <svc> first.

7. Config & Secrets

kubectl create configmap appcfg --from-literal=LOG_LEVEL=info
kubectl create secret generic dbcreds --from-literal=password=s3cr3t
# inject into a Pod
envFrom:
  - configMapRef: { name: appcfg }
env:
  - name: DB_PASSWORD
    valueFrom:
      secretKeyRef: { name: dbcreds, key: password }
# or mount as files
volumes:
  - name: cfg
    configMap: { name: appcfg }
Secrets aren't encrypted by default They're only base64-encoded in etcd. Enable encryption-at-rest and tight RBAC. Anyone who can read Secrets in a namespace can read them plainly.

8. Storage

ObjectRole
PV (PersistentVolume)A piece of cluster storage (admin/provisioner side).
PVC (PersistentVolumeClaim)A Pod's request for storage. Binds to a PV.
StorageClassTemplate for dynamic provisioning (e.g. gp3, ssd).

Access modes: RWO (one node RW), ROX (many nodes RO), RWX (many nodes RW). Most block storage is RWO; shared filesystems do RWX.

9. Scheduling controls

MechanismEffect
nodeSelectorSimple "schedule only on nodes with this label."
Affinity / anti-affinityRich rules — co-locate or spread Pods (e.g. spread replicas across zones).
Taints & tolerationsTaint a node to repel Pods; only Pods with a matching toleration land there (e.g. GPU nodes).
requestsDrive bin-packing — scheduler places by available requested resources.

Mental model: taint = node repels, toleration = pod is allowed, affinity = pod is attracted.

10. Health probes

ProbeQuestion / on fail
liveness"Is it alive?" Fail → restart the container.
readiness"Can it serve traffic?" Fail → remove from Service endpoints (no restart).
startup"Has it finished booting?" Protects slow starters from liveness killing them early.
probe trap Don't point liveness at a deep dependency (DB). If the DB blips, liveness fails and K8s restarts your healthy app pointlessly. Liveness = "is the process wedged"; readiness = "should I get traffic."

11. Rollouts & updates

spec:
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1          # extra pods allowed above replicas during update
      maxUnavailable: 0    # how many can be down (0 = zero-downtime)
kubectl set image deploy/web web=nginx:1.28
kubectl rollout status deploy/web
kubectl rollout history deploy/web
kubectl rollout undo deploy/web --to-revision=2

12. RBAC

ObjectMeaning
Role / ClusterRoleA set of permissions (verbs on resources). Role = namespaced; ClusterRole = cluster-wide.
RoleBinding / ClusterRoleBindingGrants a Role to a user / group / ServiceAccount.
ServiceAccountIdentity for Pods to talk to the API server.

Formula: Subject + Role + Binding = access. Least privilege; avoid cluster-admin.

13. Autoscaling

kubectl autoscale deploy/web --min=2 --max=10 --cpu-percent=70
  • HPA — scales Pod replicas on CPU/mem/custom metrics (needs metrics-server).
  • VPA — adjusts a Pod's requests/limits.
  • Cluster Autoscaler — adds/removes nodes when Pods can't schedule.

14. Debugging playbook

kubectl get pods                       # status column tells the story
kubectl describe pod              # Events section = why it's stuck
kubectl logs  --previous          # crashed container's last words
kubectl get events --sort-by=.lastTimestamp
kubectl get endpoints             # is the Service wired to Pods?
StatusMeaning → fix
CrashLoopBackOffApp starts then crashes repeatedly. Check logs --previous; bad config/cmd, failing liveness, missing dep.
ImagePullBackOffCan't pull image. Wrong name/tag, private registry without imagePullSecret.
PendingNo node fits. Insufficient CPU/mem requests, taints, or unbound PVC.
OOMKilledHit memory limit. Raise limit or fix the leak.
CreateContainerConfigErrorMissing ConfigMap/Secret referenced by the Pod.
0/1 Ready but RunningReadiness probe failing — app up but not serving.

15. Rapid-fire interview Q&A

  • What is a Pod?Smallest deployable unit — one or more containers sharing network namespace (same IP) and storage. Containers in a pod are always co-scheduled.
  • Deployment vs StatefulSet?Deployment = interchangeable stateless replicas, random names. StatefulSet = stable identity (web-0, web-1), stable per-pod storage, ordered rollout. Use it for databases.
  • How does a Service find its Pods?Label selector → Endpoints list. kube-proxy programs iptables/IPVS to load-balance to those Pod IPs.
  • ClusterIP vs NodePort vs LoadBalancer?Internal-only → node port on every node → cloud LB. They layer: LoadBalancer sits on NodePort sits on ClusterIP.
  • Liveness vs readiness?Liveness fail → restart container. Readiness fail → pull from Service endpoints (no restart). Startup → guard slow boots.
  • requests vs limits?requests = guaranteed/scheduled amount. limits = hard cap. Over memory limit = OOMKilled; over CPU = throttled.
  • What's in the control plane?api-server (front door), etcd (state), scheduler (placement), controller-manager (reconcile loops). Nodes run kubelet + kube-proxy + runtime.
  • How does a rolling update work?New ReplicaSet scales up while old scales down per maxSurge/maxUnavailable. Rollback = re-point to the previous ReplicaSet.
  • ConfigMap vs Secret?Same idea, Secret is for sensitive data (base64 in etcd, not encrypted by default). Mount as env or files.
  • Taint vs toleration vs affinity?Taint repels pods from a node; toleration lets a pod ignore the taint; affinity attracts pods to nodes/pods.
  • Why is my Pod Pending?Scheduler found no fit: not enough requestable CPU/mem, a taint with no toleration, or an unbound PVC.
  • What does kubelet do?Node agent — watches the API server for Pods assigned to its node and makes sure their containers run and stay healthy.
  • How is config declarative?You apply desired state; controllers run reconcile loops to converge actual → desired continuously. No imperative "start this."
  • Namespace use?Logical isolation: scoping, RBAC, resource quotas, and avoiding name collisions across teams/envs.
