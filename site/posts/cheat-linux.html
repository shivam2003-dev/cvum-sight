Linux — The Interview Cheatsheet.

linux shell devops interview-prep
The Linux an interviewer probes: files & permissions, processes & signals, what's eating resources, and enough text-tool fluency to slice a log. Everything is a file; the shell is the API.

Files & navigation

ls -la ; cd ; pwd ; find / -name "*.log" -mtime -1
cat / less / head -n 50 / tail -f file
cp -r src dst ; mv a b ; rm -rf dir ; ln -s target link
df -h ; du -sh * | sort -rh | head    # space

Permissions & ownership

chmod 644 file       # rw-r--r--   (u=rw, g=r, o=r)
chmod +x script.sh   ; chmod -R 755 dir
chown user:group file ; chgrp group file
umask 022            # default mask (new files 644, dirs 755)
# special: setuid(4) setgid(2) sticky(1) -> 4755, 1777 (/tmp)

Octal: r=4 w=2 x=1. 755 = rwx for owner, r-x group/other.

permission denied basics To enter a directory you need x on it, not r. To list it you need r. Reading a file needs r on the file and x on every parent dir.

Processes & signals

ps aux | grep nginx ; pgrep -a nginx
top / htop ; kill -TERM <pid> ; kill -9 <pid> (SIGKILL, last resort)
kill -HUP <pid>     # reload many daemons
jobs ; bg ; fg ; nohup cmd & ; disown
nice/renice ; <cmd> & (background)
SignalMeaning
SIGTERM (15)Polite stop (default kill). Catchable — graceful shutdown.
SIGKILL (9)Force kill. Uncatchable. Last resort.
SIGHUP (1)Hangup — often "reload config".
SIGINT (2)Ctrl-C.

systemd & logs

systemctl status/start/stop/restart/enable nginx
systemctl daemon-reload          # after editing a unit
journalctl -u nginx -f           # follow a service's logs
journalctl --since "1 hour ago" -p err
dmesg -T | tail                  # kernel ring buffer (OOM, hardware)

Text tools — slice a log

grep -i error app.log ; grep -rn TODO src/
grep -c 500 access.log                       # count
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head   # top IPs
sed -n '100,120p' file ; sed -i 's/old/new/g' file
cut -d: -f1 /etc/passwd ; tr -s ' ' ; wc -l
cmd1 | cmd2 ; cmd > out 2>&1 ; tee ; xargs

What's eating resources?

top ; htop                    # CPU/mem live
free -m                       # memory (look at available, not free)
vmstat 1 ; iostat -xz 1       # CPU/IO ; mpstat -P ALL 1
df -h ; df -i                 # disk space ; inodes
ss -ltnp                      # listening ports + pid
lsof -p <pid> ; lsof -i :8080

Networking basics

ip a ; ip route ; ss -tunap
curl -v https://host ; curl -I url
dig name ; nslookup name ; ping host ; traceroute host
nc -vz host port              # port open?

Packages & users

apt update && apt install pkg   # Debian/Ubuntu
yum/dnf install pkg             # RHEL/Fedora
useradd -m user ; passwd user ; usermod -aG sudo user
id ; whoami ; groups ; sudo -l

Rapid-fire Q&A

  • What does chmod 755 mean?Owner rwx, group r-x, other r-x. Octal r=4 w=2 x=1.
  • SIGTERM vs SIGKILL?TERM = graceful, catchable (cleanup). KILL(9) = forced, uncatchable. Try TERM first.
  • free shows little 'free' memory — problem?No. Linux uses free RAM as cache. Look at 'available', not 'free'.
  • How to find what's using a port?ss -ltnp or lsof -i :PORT.
  • Hard vs soft link?Hard link = another name for the same inode (same data). Soft/symlink = a pointer to a path (can cross filesystems, can dangle).
  • How to see a service's logs?journalctl -u svc -f; kernel events via dmesg.
  • stdout vs stderr redirect?> stdout, 2> stderr, 2>&1 merge stderr into stdout.
