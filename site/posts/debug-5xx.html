Debugging 5xx Surges (502 / 503 / 504).

errors reliability sre http
Each gateway 5xx points elsewhere. 502 bad gateway = upstream gave garbage/closed. 503 unavailable = no healthy upstream. 504 timeout = upstream too slow. Read the code, look at the named layer.

Decode the code

CodeGateway saysLook at
502Invalid/closed upstream responseUpstream crashed, wrong port/protocol
503No healthy backendHealth checks, 0 ready pods, overload
504Upstream too slowSlow backend, short timeout, DB stall

502 Bad Gateway

Upstream crashing; wrong port; HTTP/HTTPS or H1/H2 mismatch; upstream closed a reused keepalive.

kubectl get pods -l app=<app> ; kubectl logs <pod> --previous
kubectl get endpoints <svc>

Fix. Upstream up on expected port/protocol; align keepalive timeouts (upstream ≥ LB).

503 Service Unavailable

No backend passes health checks; all pods 0/1; selector matches nothing; rollout drained capacity; circuit breaker open.

Fix. Fix readiness; non-empty endpoints; maxUnavailable low; scale up.

503 during deploys maxUnavailable too high (or no readiness gating) drains healthy pods before new ones are Ready. Set maxUnavailable: 0 + real readiness.

504 Gateway Timeout

Upstream slower than the gateway timeout; downstream dep stalling; pool exhausted so requests queue.

Fix. Find the slow path (Latency guide); raise timeout only if work legitimately takes longer; add timeouts + circuit breakers; scale the bottleneck.
