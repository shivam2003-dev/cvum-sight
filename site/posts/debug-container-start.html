Debugging Containers That Won't Start.

containers docker debugging sre
A container that exits immediately or never starts is almost always one of: wrong entrypoint, a config/permission problem, or the main process finishing. The exit code narrows it fast — read it first, then the logs. Same logic on Docker and Kubernetes.

Read the exit code first

docker ps -a                      # STATUS shows "Exited (N)"
docker inspect <id> --format '{{.State.ExitCode}} {{.State.Error}}'
docker logs <id>
ExitMeaning
0Main process finished — no long-running foreground process.
1/2App error — read the log.
125Daemon couldn't run the container (bad flag/mount).
126Command not executable (perms / not a binary).
127Command not found (wrong path / missing in image).
137SIGKILL — usually OOM.
143SIGTERM — graceful stop.

Exits immediately with code 0

Cause. The main process ran and finished — no foreground long-running process. A container lives only as long as PID 1.

Fix. Run the server in the foreground (not backgrounded with & or as a daemon). Shells need -it. A web server must not fork-and-exit.

PID 1 = the container's life If your CMD backgrounds the app and the script ends, the container exits 0. Keep the real process in the foreground as PID 1.

127 / 126 — command not found or not executable

Cause. Wrong entrypoint path, missing binary, no execute bit, or wrong arch.

docker run --rm -it --entrypoint sh <image>    # poke around
ls -l /path/to/entrypoint ; file /path/to/binary   # exists? executable? right arch?

Fix. Correct the path; chmod +x; use exec-form CMD ["/app"]; match image arch to host.

Permission denied / read-only filesystem

Cause. Non-root user writing a root-owned path; --read-only with no tmpfs; volume owned by the wrong UID.

Fix. Write only to owned paths; mount a tmpfs for scratch; chown volumes to the container UID; on K8s set fsGroup/securityContext.

Missing config / env / mount

Cause. App crashes at boot because a required env var, config file, or secret is absent. On K8s: CreateContainerConfigError or a boot crash.

docker inspect <id> --format '{{json .Config.Env}}'
docker inspect <id> --format '{{json .Mounts}}'

Fix. Provide the env/secret/mount; fail with a clear message; validate config at startup.

Slow stop / signals ignored

Cause. Shell-form CMD wraps the app in /bin/sh -c, so PID 1 is the shell and the app never gets SIGTERM — Docker waits, then SIGKILLs (137).

Fix. Use exec form CMD ["app","--flag"], or add an init (docker run --init / tini) to forward signals and reap zombies.

Quick reference

docker ps -a ; docker logs <id> ; docker inspect <id>
docker run --rm -it --entrypoint sh <image>
kubectl describe pod <pod> ; kubectl logs <pod> --previous
