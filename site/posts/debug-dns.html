Debugging DNS Resolution Failures.

dns network sre kubernetes
DNS failures wear masks — "connection refused", random timeouts, slow first request. Test resolution directly before blaming the app. In Kubernetes, CoreDNS + ndots + search domains add traps.

Test resolution directly

dig +short example.com
dig example.com @8.8.8.8        # bypass local resolver
cat /etc/resolv.conf           # nameserver, search, ndots

Works with @8.8.8.8 but not by default → local resolver/config problem.

NXDOMAIN

Typo / record missing; wrong nameserver; not propagated; split-horizon (internal-only name). Verify the record at the authoritative server.

Kubernetes service won't resolve

# name form: <svc>.<namespace>.svc.cluster.local
kubectl -n kube-system get pods -l k8s-app=kube-dns      # CoreDNS healthy?
kubectl -n kube-system logs -l k8s-app=kube-dns

Fix. Use the full DNS name; restart CoreDNS if crashed; allow UDP/TCP 53 in NetworkPolicy.

ndots:5 tax K8s sets ndots:5, so external names get tried with every search domain first — several failing lookups. Use a trailing dot / FQDN for external names.

Slow / intermittent DNS

Search-domain fan-out, CoreDNS under-replicated, UDP conntrack races. Fix: NodeLocal DNSCache; scale CoreDNS; reduce ndots.

Quick reference

dig +short NAME ; dig NAME @8.8.8.8 ; getent hosts NAME
cat /etc/resolv.conf
kubectl -n kube-system get pods -l k8s-app=kube-dns
