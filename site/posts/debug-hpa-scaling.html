Debugging HPA & Autoscaling That Won't Scale.

kubernetes autoscaling sre hpa
Three autoscalers, three reasons they stall. HPA scales replicas on metrics — needs metrics-server + resource requests. Cluster Autoscaler adds nodes — needs schedulable-but-Pending pods. VPA resizes requests. "Won't scale" is usually missing metrics, missing requests, or a limit hit.

HPA shows <unknown> targets

Cause. HPA can't read metrics: metrics-server down, or pods have no CPU/memory requests (HPA computes % of the request).

kubectl get hpa <name> ; kubectl describe hpa <name>
kubectl top pods                 # metrics-server alive?

Fix. Install/repair metrics-server; set resources.requests; for custom metrics ensure the adapter serves.

no requests = no HPA CPU HPA is a percentage of the pod's CPU request. No request → target forever <unknown>.

HPA stuck at min

Cause. Metric below target; maxReplicas hit; stabilization window; or the metric isn't the real bottleneck (CPU low, latency high).

Fix. Raise maxReplicas; scale on a load-reflecting metric (RPS / latency via custom metrics); tune scale-up behavior.

Pods Pending — Cluster Autoscaler not adding nodes

Cause. CA only acts on pods Pending for insufficient resources that could fit a new node. Blockers: node group at max, pod too big, taints/affinity, PDB.

kubectl describe pod <pod> | grep -A10 Events
kubectl -n kube-system logs <cluster-autoscaler-pod>

Fix. Raise node-group max; ensure a node type fits requests; relax affinity/taints; read CA logs for the scale-up reason.

Scaling thrash

Fix. Set behavior.scaleDown.stabilizationWindowSeconds; widen the up/down gap; smooth the metric.

Quick reference

kubectl get hpa ; kubectl describe hpa <name>
kubectl top pods ; kubectl top nodes
kubectl get pods --field-selector=status.phase=Pending
kubectl -n kube-system logs deploy/metrics-server
