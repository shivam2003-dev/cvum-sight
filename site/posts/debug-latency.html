Debugging Latency & p99 Spikes.

latency performance sre observability
Averages lie; tail latency (p95/p99) is what users feel. Localize first — which service/hop/dependency — then attack the usual tail causes: GC pauses, lock contention, N+1 queries, cold caches, queueing. RED method + tracing.

Localize

  • Tracing — one trace shows which span eats time (app, DB, downstream, network).
  • Per-service RED dashboards — whose Duration p99 jumped.
  • Bimodal histogram = some requests hit a slow path.

GC pauses

Periodic p99 spikes with GC; whole process stalls. Fix: tune GC (G1/ZGC, GOGC); cut allocations; size heap.

Lock contention / pool exhaustion

# Java: jstack <pid> | grep -c BLOCKED
# Go:   /debug/pprof/block , /debug/pprof/mutex

Fix. Shrink critical sections; size pools; avoid global locks.

N+1 / slow dependencies

One request fans out to many small calls (trace shows dozens of sequential spans). Fix: batch/join; eager-load; cache; parallelize; add the missing index.

tail ≠ mean Mean can look fine while p99 is terrible. Alert and debug on p95/p99.

Cold caches & queueing

Post-deploy empty caches; under load, queueing (latency = queue depth / throughput) explodes p99. Fix: warm caches; add capacity before saturation; concurrency limits / load shedding.
