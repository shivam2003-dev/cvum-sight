Debugging CI/CD Pipeline Failures.

ci-cd devops sre builds
Two kinds: genuinely-bad code/test vs environment drift (flaky, cache, secrets, runner). The second wastes the most time. First question: does it fail reproducibly and locally, or only in CI?

Flaky tests

Same commit, re-run, different result. Causes: order dependence, shared state, real time/sleeps, network, races, unseeded randomness.

Fix. Isolate state; mock time/network; fix races; seed randomness; run in random order. Quarantine chronic flakes.

retry hides, doesn't fix Auto-retrying flakes masks real races that bite in prod. Track flake rate; fix top offenders.

"Works locally, fails in CI"

Environment drift: tool version, missing env var, OS/arch, uncommitted file, services available locally not in CI.

Fix. Pin versions (lockfiles, pinned images); run CI's container locally; assert env vars; never depend on uncommitted files.

Cache poisoning / stale

Build uses old deps/artifacts. Fix: key caches on a content hash (lockfile), not static; bust on dependency change; clear to confirm.

Secrets & permissions

401/403 on registry/deploy; works on main, fails on forks. Fix: scope secrets; forked-PR builds often can't see secrets by design; check token perms/expiry; OIDC over long-lived keys.

Runner OOM / limits

Job killed (137), random hangs on big builds. Fix: bigger runner; limit parallelism/heap; split the job; cache to cut peak.

Triage checklist

# 1. reproducible? re-run same commit (flaky vs real)
# 2. read the FIRST error, not the last
# 3. reproduce in CI's container locally
# 4. diff what changed: code, deps, runner image, cache key
# 5. exit code? 137=OOM, 124=timeout
