Debugging Terraform — State, Locks, Drift.

terraform iac devops sre
Terraform pain is almost always state — the map from config to real resources. Drifted, locked, out of sync, or a dependency-ordering issue. plan is your truth-teller; read it before every apply.

State lock stuck

terraform plan        # shows lock ID + who/when
terraform force-unlock <LOCK_ID>    # only if SURE no apply is running
force-unlock carefully Unlocking while another apply runs corrupts state. Confirm no CI job / teammate is mid-apply.

Drift

Plan wants to change things you didn't touch — someone changed a resource outside Terraform.

terraform plan -refresh-only
terraform apply -refresh-only      # accept reality into state

Fix. Reconcile config to reality or revert the manual change; lock down console access.

Resource exists, not in state

terraform import <address> <real-id>
terraform plan        # should now be near no-op

Tainted / replace

terraform apply -replace="aws_instance.web"

Dependency cycle

Cycle: error — bad depends_on or mutual reference. Let implicit deps (attribute references) order things.

Corrupt / out-of-sync state

Inspect with state list/state show; fix with state rm/state mv; back up state first (versioned S3). Never hand-edit unless desperate.

Quick reference

terraform plan ; terraform plan -refresh-only
terraform force-unlock <ID> ; terraform import <addr> <id>
terraform apply -replace="<addr>" ; terraform state list/show/mv/rm
TF_LOG=DEBUG terraform apply
