Debugging TLS & Certificate Errors.

tls security sre certificates
TLS errors are specific — the message names it: expired, hostname mismatch, unknown authority (broken chain), or protocol mismatch. Read the error, then verify with openssl s_client.

Inspect the live cert

openssl s_client -connect host:443 -servername host </dev/null 2>/dev/null \
  | openssl x509 -noout -dates -subject -issuer
echo | openssl s_client -connect host:443 -showcerts   # full chain

Expired / not yet valid

Fix. Renew/rotate; automate (cert-manager/ACME). "Not yet valid" on a fresh cert = clock skew — fix NTP.

clock skew looks like cert errors A wrong clock makes valid certs look expired/not-yet-valid. Check the time before re-issuing.

Hostname mismatch

Connecting by a name not in the cert SAN (CN alone is ignored), or missing SNI. Fix: issue with the right SAN; send SNI (-servername).

Unknown authority / incomplete chain

unable to get local issuer certificate — server didn't send intermediates, or client lacks the CA. Browsers cache intermediates and "work" while curl fails — a tell.

openssl s_client -connect host:443 -showcerts    # count certs sent
openssl verify -CAfile chain.pem cert.pem

Fix. Serve the full chain (leaf + intermediates); add the CA to the client trust store (update-ca-certificates).

Protocol / cipher mismatch

No shared TLS version/cipher; or mTLS expects a client cert. Fix: align versions; present client cert (-cert/-key).

Quick reference

openssl s_client -connect host:443 -servername host
openssl x509 -in cert.pem -noout -dates -subject -issuer
curl -vI https://host
kubectl describe certificate <name>     # cert-manager
