Operating System Concepts Chapter 1 — Introduction.

operating-systems chapter-1 computer-science companion-notes
This chapter gives the big picture first: an operating system makes hardware useful, safe, and easier to share.

1. Introduction

An operating system sits between applications and hardware. Without it, every program would need to control the CPU, memory, disk, keyboard, network card, and screen by itself. That would make software hard to build, hard to move, and unsafe to share.

Chapter 1 presents the operating system in two simple roles. First, it is a resource manager: it decides how CPU time, memory, storage, and devices are shared. Second, it is a control program: it makes sure programs do not break the machine or disturb each other.

This chapter also introduces the main ideas used later in the book: interrupts, kernels, user mode, kernel mode, multiprogramming, multitasking, caching, protection, virtualization, and distributed systems.

2. Detailed explanation

What an operating system is responsible for

The operating system usually does not do the user's final job itself. A browser opens a website, a compiler builds code, and a database answers a query. The OS supports all of them by creating processes, giving memory, reading files, talking to devices, handling networking, tracking time, and checking permissions.

A good mental model is this: the application asks for something, the OS checks the request, the hardware does the low-level work, and the OS returns the result in a safe way.

Computer-system organization

A computer system has one or more CPUs, main memory, and controllers for devices such as disks, keyboards, network cards, and displays. These parts work together through a shared connection path. Because the CPU and devices can work at the same time, the system needs coordination.

The operating system begins during boot. A small startup program loads the kernel into memory. The kernel then prepares devices, starts important services, and finally allows user programs to run.

Interrupts and why they matter

An interrupt is a signal that tells the CPU something needs attention. A device can raise an interrupt when input or output finishes, when a timer expires, or when hardware reports an event. Software can also force a transfer to the OS through an exception or a system call.

This matters because the CPU does not need to sit idle waiting for a slow device. For example, instead of checking again and again whether a disk read is finished, the OS can run some other program. When the disk is ready, it sends an interrupt and the OS comes back to handle it.

Storage structure and the memory hierarchy

Storage is arranged in levels. Registers and caches are very fast but very small. Main memory is bigger but loses data when power goes away. SSDs and disks are slower than RAM but keep data for a long time. Network storage can hold even more data, but it adds network delay.

The operating system helps manage this difference. It moves data between levels, keeps useful data in cache, and decides when information must be written safely to permanent storage.

Multiprogramming and multitasking

Multiprogramming means keeping several jobs in memory so the CPU always has something useful to do. If one job is waiting for disk or network I/O, the CPU can work on another job instead.

Multitasking applies the same idea to interactive systems. The OS switches quickly between programs, so it feels like many applications are running at once. This works because the scheduler regularly gets control back and decides what runs next.

Protection, security, and modes

Most modern CPUs support at least two execution modes: user mode and kernel mode. Normal applications run in user mode, where they cannot freely control hardware or execute sensitive instructions. The kernel runs in kernel mode, where it has the privilege needed to manage the system.

This split is the base of OS protection. A broken app should not overwrite another app's memory. A normal user should not be able to change kernel settings directly. An application should not read private files without permission. The OS creates and enforces these boundaries.

Virtualization and distributed systems

Virtualization allows one physical machine to act like many separate machines. A hypervisor can run multiple guest operating systems on the same hardware. Containers are lighter: they share the host kernel but isolate processes, filesystems, networking, and resource limits.

Distributed systems connect multiple machines so they can share data, computing power, or services. In that world, the OS and related system software must deal with communication, delay, machine failure, and security across the network.

4. Real-world examples

Opening a file in a code editor

When an editor opens a file, it does not control the SSD directly. It asks the OS to open the path. The OS checks permission, talks to the filesystem, reads the needed blocks, may use cache, and returns the file data.

Running music, browser, and terminal together

The machine may have fewer CPU cores than active programs. The OS scheduler gives each runnable process a short turn. While one program waits for the network or sound device, another program can use the CPU.

USB keyboard input

When you press a key, the keyboard device reports the event. It raises an interrupt, the OS handles it, and the active application finally receives the key press.

A cloud VM

A cloud VM such as an EC2 instance looks like a full computer to the guest OS. Behind the scenes, a hypervisor shares the real CPU, memory, network, and storage across many machines while keeping them isolated.

A containerized web service

A Docker container does not start its own kernel. It runs on the host kernel with isolation and resource limits. That is why containers are lighter than full virtual machines.

5. FAQs

Is the operating system the same as the kernel?

No. The kernel is the core part with full privilege. The full operating system also includes system tools, libraries, services, and utilities around it.

Why do applications need system calls?

System calls let applications ask for sensitive work without getting full control of the hardware. Opening files, creating processes, using memory, and opening network connections all go through the OS.

Why are interrupts better than constant polling?

Polling means checking again and again whether a device is ready. That wastes CPU time. Interrupts let the CPU do other work and respond only when needed.

Why does the OS need a timer?

A timer stops one program from using the CPU forever. When the timer fires, the OS gets control back and can decide what should run next.

What makes caching risky?

A cache stores copies of data. If the copy is old, a program may read stale information. The OS must decide when cached data should be updated or written back.

How is protection different from security?

Protection is about enforcing access rules inside the system. Security is a wider topic that also includes attacks, stolen credentials, data leaks, and misuse from outside the system.

6. Key takeaways

  • An operating system makes hardware easier and safer to use.
  • The OS manages CPU time, memory, files, devices, and network access.
  • Interrupts help the system respond to events without wasting CPU time.
  • User mode and kernel mode protect the machine from unsafe program behavior.
  • Multiprogramming and multitasking keep systems busy and responsive.
  • Different storage levels trade speed, size, cost, and persistence.
  • Caching improves speed but can create consistency problems.
  • Virtualization and distributed systems apply OS ideas at larger scale.

7. Conclusion

Chapter 1 is the foundation for the rest of operating systems. It explains why the OS exists: to turn complex hardware into a platform that programs and users can depend on.

Once you understand interrupts, the kernel boundary, resource sharing, and protection, the rest of the subject becomes easier. Processes, scheduling, memory, filesystems, I/O, security, virtualization, and distributed systems are all connected parts of the same job.
