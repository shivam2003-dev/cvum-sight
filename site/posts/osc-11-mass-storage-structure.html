Operating System Concepts Chapter 11 — Mass-Storage Structure.

// the one-minute version

Persistent storage is where data lives when the power's off. Hard disks are mechanical — a head seeks across spinning platters, so order matters and the OS uses disk scheduling (SCAN, C-SCAN) to cut seek time. SSDs have no moving parts, so scheduling matters far less but wear does. RAID combines multiple drives for speed, redundancy, or both.

RAM forgets everything when you unplug. Storage is where your files actually survive. But storage is also achingly slow compared to RAM — especially the spinning kind — so a huge amount of OS cleverness goes into ordering and arranging disk work to hide that slowness.

01 Hard disks: mechanical and order-sensitive

A hard disk has spinning platters and a read/write head on a moving arm. To read a block, the head must seek to the right track and wait for the platter to rotate the data under it. Seek time dominates, and it depends on where the head is now — so the order you service requests changes total time dramatically.

02 SSDs: electronic and different

A solid-state drive stores data in flash with no moving parts. There's no seek, so random access is roughly as fast as sequential, and disk-scheduling tricks barely help. But flash cells wear out after many writes, so SSDs add wear leveling to spread writes evenly, and writing requires erasing whole blocks first — a different cost model entirely.

03 Disk scheduling

When several disk requests are pending, the OS picks the order. On an HDD, a smart order means far less head travel:

FCFS

Serve requests in arrival order. Fair but the head can bounce wildly across the disk, wasting seek time.

SCAN (elevator)

The head sweeps in one direction servicing requests, then reverses — like an elevator. Smooth and efficient; no wild jumps.

C-SCAN

Like SCAN but always sweeps the same direction, snapping back to the start at the end. Gives more uniform wait times across the disk.

think of it likeDisk scheduling is an elevator's logic. A good elevator doesn't chase button-presses in the order they were pushed — it sweeps up servicing every request, then sweeps down. SCAN is literally called the elevator algorithm for this reason.
noteOn an SSD, all of this mostly evaporates: with no seek penalty, request order barely affects performance. Disk scheduling is a story about mechanical storage, and matters less every year as SSDs take over — but the elevator idea is a classic worth knowing.

04 RAID: many drives, one goal

RAID (redundant array of independent disks) combines several drives to gain speed, reliability, or both. The common levels:

LevelTechniqueGives you
RAID 0striping (split data across drives)speed — but zero redundancy; one drive dies, all data lost
RAID 1mirroring (full copy on a second drive)redundancy — survives a drive failure; costs double the disks
RAID 5striping + distributed paritygood speed + survives one drive failure, efficient on space
RAID 6striping + double paritysurvives two simultaneous drive failures
watch outRAID is not a backup. RAID 1/5/6 protect against drive hardware failure, but they happily replicate a deleted file, a ransomware encryption, or a bad write to every disk instantly. You still need real backups for human error and corruption.

05 Swap space

Storage also backs virtual memory: swap space is the disk area where the OS parks pages evicted from RAM (Chapter 10). Because swapping touches the disk, fast swap storage and keeping swapping rare both matter — heavy swapping is exactly the thrashing that wrecks performance.

06 Questions students actually ask

Why does request order matter so much on a hard disk?

Because the mechanical head must physically seek to each location, and seek time dominates. Servicing nearby requests together (instead of in arrival order) drastically cuts total head travel and speeds everything up.

Why doesn't disk scheduling help SSDs much?

SSDs have no moving head and no seek penalty, so a random block is about as fast to reach as a sequential one. Reordering requests for locality — the whole point of disk scheduling — buys almost nothing.

Is RAID a substitute for backups?

No. RAID protects against drive hardware failure, but it instantly mirrors mistakes — deletions, corruption, ransomware — onto every disk. Backups protect against those; RAID protects against a dead drive. You need both.

What is swap space?

Disk space the OS uses to hold memory pages evicted from RAM under virtual memory. It lets the system pretend to have more RAM than it does, at the cost of slow disk access when those pages are needed again.

07 Key takeaways

  • Storage persists data without power but is far slower than RAM.
  • HDDs are mechanical, so request order (disk scheduling) hugely affects speed.
  • SCAN/C-SCAN sweep the head like an elevator to minimize seeks.
  • SSDs have no seek, so scheduling barely matters, but writes wear cells out.
  • RAID combines drives for speed (0), redundancy (1), or both (5/6) — but isn't a backup.
  • Swap space on disk backs virtual memory.
