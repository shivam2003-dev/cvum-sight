Operating System Concepts Chapter 5 — CPU Scheduling.

operating-systemschapter-5computer-sciencecompanion-notes
CPU scheduling decides which ready task runs next. That one decision shapes system responsiveness, throughput, fairness, and user experience.

1. Introduction

The CPU is usually the most important shared resource in a system. When many runnable processes want it at once, the scheduler chooses who runs next and for how long.

This chapter is important because scheduling is where OS theory becomes visible to users. Bad scheduling feels like lag, unfairness, or wasted performance.

2. Detailed explanation

Scheduling goals

Different systems care about different goals: CPU utilization, throughput, turnaround time, waiting time, response time, and fairness.

Preemptive and non-preemptive scheduling

In non-preemptive scheduling, a process keeps the CPU until it blocks or finishes. In preemptive scheduling, the OS can interrupt it and give the CPU to another process.

Classic algorithms

Common strategies include FCFS, SJF, priority scheduling, and round robin. Each algorithm helps one goal more than another. For example, round robin improves responsiveness, while shortest-job ideas can reduce average waiting time.

Starvation and fairness

If the scheduler always favors certain jobs, some tasks may wait too long. Aging and similar policies help reduce starvation.

Multicore scheduling

Modern systems often have many cores. The OS must decide not only who runs, but also where they run. Load balancing and CPU affinity become important here.

3. Key concepts

ConceptMeaning
SchedulerThe OS logic that chooses the next process or thread to run.
PreemptionTaking the CPU away from a running task.
Response timeHow quickly a system starts reacting to a request.
Turnaround timeTotal time from job submission to completion.
Round robinA time-slice based scheduling approach.
CPU affinityA preference for keeping work on a specific core.

4. Real-world examples

Desktop interaction

Interactive apps need quick response, so the scheduler should not let background work freeze the UI.

Batch processing

Long analytics jobs may care more about throughput than instant response.

Multicore web service

A busy service must spread worker load across cores without too much movement overhead.

5. FAQs

Is there one best scheduling algorithm?

No. The best choice depends on system goals.

Why is preemption useful?

It prevents one task from blocking everyone else for too long.

Can fairness hurt performance?

Sometimes. The OS often balances fairness against throughput and latency.

Why does multicore scheduling feel harder?

Because the scheduler must manage both time sharing and core placement.

6. Key takeaways

  • Scheduling controls responsiveness and efficiency.
  • Different workloads need different priorities.
  • Preemption is essential for interactive systems.
  • Fairness and performance can pull in different directions.
  • Multicore systems add placement and balancing problems.

7. Conclusion

Chapter 5 shows that scheduling is a policy problem, not just a mechanism problem. The OS must decide what “good” means for the system, then schedule accordingly.
