Chapter 10 — On-policy Control with Approximation, explained.

controlsemi-gradient-sarsaaverage-rewardcontinuing-tasks

// the one-minute version

Extending approximate value functions to action selection, episodic semi-gradient Sarsa, and average-reward control for continuing tasks.

Prediction tells a driver how promising each situation is. Control must compare steering choices and improve behavior while the same function approximator generalizes across an enormous state–action space.

01 The chapter in one mental model

core loopw ← w + α[Gₜ:ₜ₊ₙ − q̂(Sₜ,Aₜ,w)]∇q̂(Sₜ,Aₜ,w).

The notation can look dense, but the purpose is practical: turn experience into a better prediction or a better decision. Read every equation by naming what is known now, what new evidence arrived, and which estimate is being moved toward that evidence.

02 Approximate action values

Features now represent state–action pairs. A single parameter update changes estimates for many related decisions, enabling control in spaces where a Q-table is impossible.

03 Episodic semi-gradient Sarsa

The n-step Sarsa target is combined with a differentiable action-value approximation. An ε-greedy policy supplies exploration while staying on-policy.

04 Mountain-car intuition

Immediate progress may require first moving away from the goal to build momentum. This example shows why delayed return and generalization must work together across continuous states.

05 Average reward

For a continuing task with no natural termination, optimize long-run reward per step rather than a discounted sum. Differential returns measure reward relative to the current average reward rate.

06 Discounting debate

Discounting is mathematically convenient and models preference for immediacy, but in continuing control it can complicate the objective. Average-reward formulations directly express steady-state performance.

07 Worked example

walk it throughAn HVAC controller runs forever. Episodic framing would require artificial resets. Average-reward control can optimize comfort minus energy cost per minute, while differential values capture whether an action is better than the system's usual long-run rate.

When you work through an example, keep the roles separate: the behavior policy produces experience, the target says what the current estimate should move toward, and the step size controls how far it moves. Many algorithms differ mainly in one of those three choices.

08 The easy mistake

watch outTurning a tabular algorithm into a neural algorithm is not just replacing Q[s,a] with a network call. Generalization couples updates, policy changes alter the data distribution, and stability becomes a central design issue.

09 Questions people actually ask

Do I need to memorize every equation?

No. First learn the update pattern: old estimate plus step size times an error. Then identify how the target is built and whether data comes from the same policy being evaluated. Derive or look up the exact form after the mental model is stable.

What should I implement first?

Use the smallest environment that exposes the chapter's idea. Print intermediate values, fix random seeds for debugging, and compare against a simple baseline before scaling to a neural network.

How do I know whether learning is real?

Evaluate on multiple seeds, separate training behavior from the target or greedy policy, report distributions rather than one run, and inspect learned values or policies—not only total reward.
