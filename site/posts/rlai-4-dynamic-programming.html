Chapter 4 — Dynamic Programming, explained.

dynamic-programmingpolicy-iterationvalue-iterationgpi

// the one-minute version

How a known environment model enables policy evaluation, policy improvement, policy iteration, value iteration, and generalized policy iteration.

If you know every transition probability and reward, you do not need to learn by bumping into the world. You can repeatedly ask, “What would happen if…?” Dynamic programming turns a complete model into value estimates and an optimal policy.

01 The chapter in one mental model

core loopPolicy evaluation backs up expected returns; policy improvement chooses actions greedy with respect to those values.

The notation can look dense, but the purpose is practical: turn experience into a better prediction or a better decision. Read every equation by naming what is known now, what new evidence arrived, and which estimate is being moved toward that evidence.

02 Iterative policy evaluation

Start with arbitrary values and repeatedly apply the Bellman expectation backup for every state. Each sweep propagates reward information backward until values are self-consistent for the policy.

03 Policy improvement

After evaluating π, compare actions using one-step lookahead. Choosing a maximizing action cannot make the policy worse. This is the policy-improvement theorem in practical form.

04 Policy iteration

Alternate complete evaluation and greedy improvement. For finite MDPs, the process reaches an optimal policy after finitely many policy changes, though exact evaluation may be unnecessarily expensive.

05 Value iteration

Combine truncated evaluation and improvement in a single optimality backup. Each sweep takes the best action immediately, converging toward optimal values with less bookkeeping.

06 Generalized policy iteration

Evaluation and improvement need not finish before the other begins. They can interact at different speeds as long as values move toward the current policy and the policy moves toward greediness.

07 Worked example

walk it throughIn a gridworld, terminal cells pay 0 and each move costs −1. Policy evaluation estimates remaining steps under a random policy. Greedy improvement points toward neighbors with better values. Repeating this produces shortest-path behavior.

When you work through an example, keep the roles separate: the behavior policy produces experience, the target says what the current estimate should move toward, and the step size controls how far it moves. Many algorithms differ mainly in one of those three choices.

08 The easy mistake

watch outDynamic programming is not usually practical for large real environments: it requires a model and sweeps over the state space. Its importance is conceptual—later sample-based methods approximate the same backups without exhaustive knowledge.

09 Questions people actually ask

Do I need to memorize every equation?

No. First learn the update pattern: old estimate plus step size times an error. Then identify how the target is built and whether data comes from the same policy being evaluated. Derive or look up the exact form after the mental model is stable.

What should I implement first?

Use the smallest environment that exposes the chapter's idea. Print intermediate values, fix random seeds for debugging, and compare against a simple baseline before scaling to a neural network.

How do I know whether learning is real?

Evaluate on multiple seeds, separate training behavior from the target or greedy policy, report distributions rather than one run, and inspect learned values or policies—not only total reward.

10 Key takeaways

  • Iterative policy evaluation: Start with arbitrary values and repeatedly apply the Bellman expectation backup for every state.
  • Policy improvement: After evaluating π, compare actions using one-step lookahead.
  • Policy iteration: Alternate complete evaluation and greedy improvement.
  • Value iteration: Combine truncated evaluation and improvement in a single optimality backup.
  • Generalized policy iteration: Evaluation and improvement need not finish before the other begins.
