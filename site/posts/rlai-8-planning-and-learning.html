Chapter 8 — Planning and Learning with Tabular Methods, explained.

dynamodel-basedplanningprioritized-sweepingmcts

// the one-minute version

How learned models turn experience into simulated experience through Dyna, prioritized sweeping, rollout planning, and Monte Carlo tree search.

A model-free agent learns only once from each real transition. A planning agent can remember that transition, imagine it again, and improve many related decisions while the real environment is idle.

01 The chapter in one mental model

core loopDyna loop: act → learn value → learn model → sample model experiences → learn again.

The notation can look dense, but the purpose is practical: turn experience into a better prediction or a better decision. Read every equation by naming what is known now, what new evidence arrived, and which estimate is being moved toward that evidence.

02 Models and planning

A distribution model predicts possible next states and rewards; a sample model produces one simulated transition. Planning means applying familiar value updates to model-generated experience.

03 Dyna architecture

Dyna interleaves direct RL, model learning, and planning. The same update rule can consume both real and simulated transitions, making implementation conceptually clean.

04 When models are wrong

A learned model becomes stale after the environment changes. Dyna-Q+ adds an exploration bonus for long-untried actions, encouraging the agent to test whether old knowledge remains valid.

05 Prioritized sweeping

Uniform planning wastes backups on states whose values barely changed. Prioritized sweeping works backward through predecessor states with large expected changes, focusing compute where it can matter.

06 Decision-time planning

Rollouts and Monte Carlo tree search plan from the current state rather than improving a global policy everywhere. MCTS repeatedly selects, expands, simulates, and backs up within a search tree.

07 Worked example

walk it throughA warehouse robot experiences that aisle B is blocked. Direct learning changes the value of the current route. A model also updates imagined routes that would later enter B. Prioritized sweeping quickly revises upstream junctions rather than replaying irrelevant corridors.

When you work through an example, keep the roles separate: the behavior policy produces experience, the target says what the current estimate should move toward, and the step size controls how far it moves. Many algorithms differ mainly in one of those three choices.

08 The easy mistake

watch outModel-based does not mean the model must be a perfect simulator. Even a partial model can accelerate learning, but planning must account for model error and spend computation selectively.

09 Questions people actually ask

Do I need to memorize every equation?

No. First learn the update pattern: old estimate plus step size times an error. Then identify how the target is built and whether data comes from the same policy being evaluated. Derive or look up the exact form after the mental model is stable.

What should I implement first?

Use the smallest environment that exposes the chapter's idea. Print intermediate values, fix random seeds for debugging, and compare against a simple baseline before scaling to a neural network.

How do I know whether learning is real?

Evaluate on multiple seeds, separate training behavior from the target or greedy policy, report distributions rather than one run, and inspect learned values or policies—not only total reward.

10 Key takeaways

  • Models and planning: A distribution model predicts possible next states and rewards; a sample model produces one simulated transition.
  • Dyna architecture: Dyna interleaves direct RL, model learning, and planning.
  • When models are wrong: A learned model becomes stale after the environment changes.
  • Prioritized sweeping: Uniform planning wastes backups on states whose values barely changed.
  • Decision-time planning: Rollouts and Monte Carlo tree search plan from the current state rather than improving a global policy everywhere.
