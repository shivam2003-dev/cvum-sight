TurboQuant — What If Compressing AI Memory Was Just a Random Spin.

paperjuice ml quantization kv-cache vector-search

You're running a large language model. Context window is 128K tokens. Every single token stores a key and a value vector — in full 16-bit precision — for every layer, for every attention head. Your GPU is sweating. Memory is full. And the model hasn't even started generating yet.

This is the KV cache problem. The longer the conversation, the more memory your model needs just to remember what it already read. It's like a student who photocopies every textbook page in full color when they only need the key points in pencil.

Researchers at Google Research, Google DeepMind, and NYU asked: what if we could compress those vectors to 2–4 bits per number without losing the math that matters? Their answer is TurboQuant, and the core trick is almost absurdly simple.

The problem: compression that doesn't destroy geometry.

Vector quantization has been around since Shannon. The goal: take a high-dimensional vector (like a 128-number embedding) and represent it with far fewer bits — while keeping the important relationships intact.

"Important relationships" means two things: the vectors should look similar after decompression (low MSE), and the dot products between vectors should stay accurate (inner product preservation). That second one is critical — every attention layer in a transformer is literally computing dot products between queries and keys.

Existing methods fall into two camps. Offline methods like GPTQ and AWQ study your data, compute Hessians, and calibrate quantization maps. They work well but need heavy preprocessing — useless when new data streams in token by token. Online methods work instantly but their compression quality is suboptimal — they leave performance on the table at every bit-width.

That's not engineering. That's picking between slow-and-good or fast-and-sloppy.

The big idea: spin your vector, then round each number.

TurboQuant's insight fits in one sentence: randomly rotate the vector first, then quantize each coordinate independently with a precomputed optimal scalar quantizer.

That's it. That's the core algorithm. But why does something so simple work so well?

1. Random rotation makes any vector look the same.

Imagine you have a vector that's "spiky" — most of its energy is concentrated in a few coordinates. If you try to quantize each coordinate independently, the big values get crushed and the small values waste their bits on near-zero numbers.

Now multiply that vector by a random rotation matrix. The result is a vector that's uniformly spread across the unit sphere. Every coordinate follows the same Beta distribution (which looks like a Gaussian bell curve in high dimensions). No spikes. No wasted bits. Every coordinate carries roughly the same amount of information.

It's like shuffling a deck of cards before dealing. The original order doesn't matter anymore — every hand looks statistically the same.

2. Independent coordinates = embarrassingly simple quantization.

Here's the beautiful consequence. After rotation, the coordinates are nearly independent in high dimensions. That means you can quantize each one separately — just round it to the nearest value in a precomputed codebook — without worrying about correlations between coordinates.

The codebook itself comes from solving a 1D k-means problem (the classic Lloyd-Max algorithm) against the Beta distribution. You solve this once, store the centroids, and reuse them forever. No per-data calibration. No learning. No gradient descent.

To dequantize, you look up the centroids and reverse-rotate. Done.

3. Two-stage trick for unbiased inner products.

Here's where the paper gets clever. MSE-optimal quantization — the kind that minimizes reconstruction error — introduces bias when you use the quantized vectors for dot products. At low bit-widths, this bias is significant.

TurboQuant's fix: a two-stage pipeline. First, apply the MSE quantizer with one fewer bit than your budget. Then take the residual (the error between original and quantized vector), and compress that with a 1-bit quantizer called QJL (Quantized Johnson-Lindenstrauss transform).

The QJL part is provably unbiased for inner products. So the combination gives you: MSE-optimal compression from stage one, plus unbiased inner product estimation from stage two. Both for the price of one extra bit per coordinate.

It's like taking a photo at slightly lower resolution, then adding a thin correction layer that fixes only the colors that matter for comparison — not reconstruction.

The method: step by step.

Here's the full TurboQuant pipeline, broken down:

  1. Normalize the input vector to unit length. Store the norm separately.
  2. Randomly rotate using a shared rotation matrix (generated once via QR decomposition of a random Gaussian matrix).
  3. Quantize each coordinate independently: find the nearest centroid in the precomputed codebook. Store the index (b bits per coordinate).
  4. (For inner product mode) Compute the residual, apply QJL (a 1-bit sign-based sketch), and store the sign vector.
  5. Dequantize: look up centroids, reverse-rotate, rescale by stored norm.

Every step is a matrix multiply or a table lookup. No loops over data. No iterative optimization. Fully vectorizable on GPUs. The paper calls it "data-oblivious" — it doesn't need to see your data before compressing it.

The results: quality neutrality at 3.5 bits.

This is where TurboQuant stops being elegant math and starts being practical.

  • Needle-in-a-Haystack test: TurboQuant at 4× compression scores 0.997 — identical to the full-precision model (also 0.997). SnapKV scores 0.858. KIVI scores 0.981.
  • LongBench generation: At 3.5 bits per channel, TurboQuant achieves "absolute quality neutrality" — performance indistinguishable from the uncompressed model.
  • At 2.5 bits: Only marginal degradation while compressing by more than 4.5×.
  • Nearest neighbor search: TurboQuant outperforms Product Quantization in recall across all dimensions (200, 1536, 3072) — and here's the kicker — with indexing time near zero.

Read that last point again. Product Quantization takes 240 seconds to index 100K vectors in 1536 dimensions. RabitQ takes 2,268 seconds. TurboQuant? 0.0013 seconds. That's not a typo. Five orders of magnitude faster.

The surprise: it's provably close to the theoretical limit.

Here's something I didn't expect from a method this simple.

The authors prove an information-theoretic lower bound on the best distortion any quantizer can achieve — using Shannon's source coding theory and Yao's minimax principle. Then they show TurboQuant's distortion is within a factor of ≈ 2.7× of this absolute floor. At 1-bit width, the gap shrinks to just 1.45×.

For context: this means no algorithm — no matter how clever, how much data it sees, how long it runs — can be more than 2.7× better than TurboQuant at any bit-width. And TurboQuant runs in microseconds with zero data dependence.

The math community calls this "near-optimal." I'd call it "suspiciously close to perfect for something that's basically just random rotation plus rounding."

Why should you care?

  1. Longer conversations, less memory. If you're serving LLMs with long context windows, TurboQuant lets you compress the KV cache by 4.5× with negligible quality loss. That's the difference between running on one GPU and needing two.
  2. Vector search gets free compression. For RAG pipelines and vector databases, TurboQuant replaces Product Quantization with better recall and essentially zero indexing time. No codebook training. No k-means. Just rotate and round.
  3. Online quantization is now solved. TurboQuant works on streaming data — each vector is compressed independently the moment it arrives. No calibration sets, no offline preprocessing, no second pass over the data.

The one-paragraph version.

TurboQuant compresses high-dimensional vectors by randomly rotating them (so every coordinate follows the same known distribution), then applying precomputed optimal scalar quantizers to each coordinate independently. For inner product tasks, it adds a 1-bit correction on the residual to remove bias. The result is a data-oblivious, online, GPU-friendly quantizer that achieves near-optimal distortion at every bit-width — within 2.7× of the information-theoretic lower bound — while matching full-precision LLM performance at just 3.5 bits per channel.

The napkin takeaway.

If vector quantization is packing for a trip, then:

  • Offline methods (GPTQ, AWQ) = unpacking everything, weighing each item, repacking perfectly — but it takes an hour every time you travel
  • Simple online methods (KIVI) = shoving everything in the bag randomly — fast but half your stuff gets crushed
  • TurboQuant = shaking the bag so everything settles evenly, then vacuum-sealing each layer — instant, optimal, and nothing gets damaged

Same suitcase. Same clothes. One packs in microseconds and loses almost nothing.

Paper: "TurboQuant: Online Vector Quantization with Near-optimal Distortion Rate" — Amir Zandieh, Majid Daliri, Majid Hadian, Vahab Mirrokni. Google Research, NYU, Google DeepMind. arXiv:2504.19874, April 2025.

// vocab

vector quantization ▶
Compressing a high-dimensional vector (a list of numbers) into fewer bits while keeping its geometric properties — distances and dot products — approximately correct.
KV cache ▶
Key-value cache. During text generation, transformers store the key and value vectors from all previous tokens so they don't have to recompute them. Grows linearly with context length and eats GPU memory fast.
MSE distortion ▶
Mean squared error between the original vector and its reconstructed (dequantized) version. Lower is better — means the compressed version looks more like the original.
inner product distortion ▶
How much error quantization introduces into dot products between vectors. Critical for attention (queries dot keys) and nearest neighbor search (similarity scoring).
data-oblivious ▶
An algorithm that works without knowing anything about the input data in advance. No calibration, no training set, no preprocessing. Each input is handled independently.
QJL (Quantized JL) ▶
A 1-bit quantization method based on the Johnson-Lindenstrauss transform. Projects a vector through a random matrix and keeps only the signs. Provably unbiased for inner product estimation.
Lloyd-Max quantizer ▶
The optimal way to partition a 1D distribution into buckets that minimize mean squared error. Basically k-means in one dimension. TurboQuant uses it to find the best rounding thresholds.
Shannon lower bound ▶
A theoretical floor on how much distortion any compression scheme must introduce for a given bit budget. Derived from information theory. No algorithm can beat it — only approach it.
