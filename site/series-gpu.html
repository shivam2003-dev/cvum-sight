SERIES // GPU · FROM A SINGLE WARP TO A WHOLE DATACENTER

GPU Programming & Optimization.

Six articles, one repeating idea: keep the expensive resource busy by hiding the latency of the slower level below it. Start from the silicon (SIMT, warps, the memory hierarchy), learn the rules the hardware rewards (coalescing, shared memory, occupancy), get a repeatable optimization method (the Roofline model and the modern toolchain — Nsight, CUTLASS, TensorRT, Triton, Helion), then scale out to many GPUs (model parallelism, Megatron-LM) and a whole datacenter (scheduling, virtualization, multi-tenancy). Plain language, deep technical detail, built from the canonical books, NVIDIA/AMD whitepapers, and the research literature.

PHASE 1 — ARCHITECTURE

1.1 · beginner

How a GPU actually works — SIMT, warps & the silicon

A GPU is a throughput machine, not a fast CPU. Threads run in lock-step warps of 32; the SM hides memory latency by switching warps for free. The memory hierarchy, and how it maps onto Ampere, Hopper, RDNA & CDNA.

 1.2 · intermediate

GPU memory — coalescing, shared memory & occupancy

The three rules that decide kernel speed: coalesce a warp's 32 reads into one transaction, stage reused data in shared memory (and dodge bank conflicts), and keep enough warps resident to hide the rest.

PHASE 2 — OPTIMIZATION

2.1 · intermediate

Kernel optimization & the Roofline model

Measure before you optimize. Arithmetic intensity and the Roofline model tell you whether you're memory- or compute-bound — and that decides which technique family (the Hijma taxonomy) can possibly help.

 2.2 · intermediate

The GPU toolchain — profilers & kernel DSLs

Nsight Systems & Compute to see what's slow; CUTLASS, TensorRT, Triton & Helion to write fast kernels without raw PTX. Pick the highest rung of the abstraction ladder that meets your needs.

PHASE 3 — SCALE

3.1 · advanced

Multi-GPU & model parallelism

Past one GPU, communication is the bottleneck. Data, tensor, pipeline & sequence parallelism; Megatron-LM; the NVLink-vs-InfiniBand rule; and why synchronization and access overhead — not raw compute — decide scaling.

 3.2 · advanced

GPU datacenters — scheduling & multi-tenancy

Why a $40M cluster sits half-idle, and the two fixes: scheduling (the Wei Gao taxonomy) and sharing (MIG, MPS, time-slicing, kernel interception) — under the hard constraints of isolation and predictable performance.

THE ONE IDEA, AT SIX SCALES

  • Warp scheduling hides HBM latency behind other warps.
  • Occupancy & coalescing keep the ALUs fed from memory.
  • Fusion raises arithmetic intensity so you move fewer bytes per FLOP.
  • Comm/compute overlap hides interconnect latency at cluster scale.
  • Topology-aware scheduling & sharing keep the whole fleet busy.
  • One principle — hide latency, pack the resource — from 32 threads to 32,000 GPUs.
